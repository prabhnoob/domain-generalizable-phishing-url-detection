    This course is project driven. Students will work in teams to define, develop, and complete a project in the field
    of data mining/machine learning over the course of one semester. Each team will consist of undergraduate
    students and one graduate student, who serves as the project lead, coordinating the project and guide the team
    through the research and development process. The course project has two main objectives:

            -    Hands-on experience: Gain practical experience in applying data mining and machine learning methods
                 to a real-world problem, while developing skills in project planning, implementation, evaluation, and
                 teamwork.
            -    Research experience: Develop an understanding of the research process, from identifying a problem
                 and reviewing existing approaches to designing, implementing, and evaluating a solution.

    Projects should aim to advance the state of the art, rather than simply reproduce an existing solution. This
    provides students with an opportunity to conduct meaningful research while completing the course requirements.

    A research project typically starts with a problem and proposes a solution by designing, implementing, and
    evaluating an algorithm or computational approach. In this sense, it may resemble a software project; however,
    there are important differences. A software project may primarily focus on implementing or integrating existing
    algorithms to build a functional system. In contrast, a research project should aim to investigate a problem,
    identify a limitation or gap in existing approaches, and propose a solution that addresses that gap. The proposed
    solution may involve (1) a new algorithm, (2) a modification or extension of an existing algorithm, (3) a new
    combination/pipeline of existing techniques, or (4) a novel application of existing methods to a problem where
    they have not been adequately explored. Therefore, the goal is not simply to implement an existing method, but
    to make a meaningful contribution beyond what has already been done, supported by appropriate experiments
    and evaluation. Roughly, a research project consists of the following milestones (phases):

    1. Project Definition & Team Formation (Proposal)
    2. Background & Related Work (Literature Review)
    3. Solution Design & Implementation (Proposed Solution or Method)
    4. Evaluation (Experimentation)
    5. Project Presentation: 3-Minute Talk (3MT)
    6. Project Management & Documentation (Graduate Student Only, Umbrella Activity)

    A project manual has been prepared to guide students through each milestone. Each milestone breaks the project
    into a series of smaller steps and deliverables. The current manual covers Milestone 3: Solution Design &
    Implementation, also known as Proposed Solution or Method.

                                  3.1. Formal Definition: Input & Output (Solution)
    At a very high level of abstraction, any proposed method for solving a problem can be viewed as a function that
    takes some input, performs a finite sequence of processing and/or calculations, and produces an output (i.e., a
    solution). For example, suppose your proposed method is to “cluster people into groups of like-minded people”.

    differently:

       -   Can a person belong to multiple groups?

                                          3.2. Formal Definition: Algorithm
    So far, we have formally specified the input and output of our proposed solution. We now need to describe how
    our method transforms the input into the desired output. In a Data Mining or Machine Learning project, this
    usually means specifying how the raw data are:

       -   represented in a form suitable for computation;
       -   preprocessed or transformed;
       -   used to construct relevant embeddings, points, features or representations;
       -   provided to a data mining or machine learning algorithm/model; and
       -   transformed into the final prediction, ranking, clustering, recommendation, or other solution.

    understand exactly what your method does, without having to guess important details. Depending on your
    project, this may include:

    information is provided to the model, what the model computes, and how its output becomes the final solution.

    Important: Formalizing a proposed solution can be challenging. That is expected. The goal is not to make the
    mathematics unnecessarily complicated, but to remove ambiguity and precisely communicate what your
    proposed method is supposed to produce.

                                           3.3. Formal Definition: Pseudo-code
    You need to support your formal algorithmic description with pseudo-code. Pseudo-code is not your program
    written line-by-line in a specific programming language. Instead, it describes the overall logic and flow of your
    solution using a language-independent notation, including important steps necessary to transform the input into
    the final solution, such that a reader can understand what the solution does without reading the source code.

    3.5.1. Reproducible and Repeatable Results
    Your implementation should also produce reproducible/repeatable results when the same input and settings are
    used. There are different definitions and distinctions between reproducibility and replicability in the academic
    community. For the purpose of this course, the practical expectation is that “given the same input data, code,
    configuration, and random seed, another person should be able to run your implementation and obtain the
    same results.” For instance, if your report says that if P={p1, p2, p3}, then f(P)={{p1, p3},{p2}}, then someone
    downloading your repository should be able to provide the same input P={p1, p2, p3} and obtain the same result
    f(P)={{p1, p3},{p2}} under the same experimental settings. Many machine learning algorithms contain
    randomized operations. In such cases, you should explicitly control the random seed where possible. For
    example, in Python:

    import random
    random.seed(0)
    import torch
    torch.manual_seed(0)
    import numpy as np
    np.random.seed(0)

    If your method uses additional libraries or sources of randomness, you should also consider whether their random
    states need to be controlled.
