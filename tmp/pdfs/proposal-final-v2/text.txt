Phishing websites copy real websites to steal passwords and money.
Most machine-learning tools that catch phishing links are tested
the easy way: the data is shuffled first, so the same website family
can end up in both training and testing. This makes the tool look
better than it really is. We test detectors the honest way, using test
websites from domains the model has never seen, and measure how
much accuracy drops once the shortcuts are removed.

In plain words, given a link, decide whether it is phishing or safe
without ever training on that link’s own website. Formally, let U
be the set of all URLs, Y = {0, 1}, where 1 means phishing and 0
means safe, and let 𝑟 : U → R map a URL to its registrable domain.

Introduction and Motivation

Phishing is when a fake link pretends to be a trusted website to steal
someone’s login or payment details. In 2025 alone, security groups
tracked over 3.8 million phishing attacks [2]. A good detector could
catch these links before anyone clicks them. Past work already
reports very accurate results [3], but that only matters if the detector
also catches brand-new attacker websites, not just ones like its
training data.

Gap and Project Objective

Most testing methods split data randomly, so subdomains of one
company, such as mail.paypal.com, can land in both sets. Then
the model is not really tested on anything new because it already
learned about that company. Cross-dataset transfer is difficult
enough that a specialized domain-adaptation method recovered
only 0.06 F1 on average and up to 0.2 in the best case [4]. Even a
newer 2026 method that splits by host still allowed 1,387 matching
domains to leak across [1].
We will use the registrable domain (for example, paypal.com)
as the one thing that must never repeat between training and testing. We compare a random split, a host-disjoint split, a registrabledomain-disjoint split, and a cross-source split on a second dataset.
Experiments use the 235,795-site PhiUSIIL corpus [3] plus an independent public URL corpus. Our contribution is a fair, reusable test
protocol and a real number for how much the old style of testing
overstated performance.
