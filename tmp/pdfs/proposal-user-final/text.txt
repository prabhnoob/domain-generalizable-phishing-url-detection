3

Phishing websites copy real websites to steal passwords and money.
Most machine-learning tools that catch phishing links are tested
the easy way: the data is shuffled first, so the same website family
can end up in both training and testing. This makes the tool look
better than it really is. We test detectors the honest way, using test
websites from domains the model has never seen, and measure how
much performance drops once these shortcuts are removed.

In plain words, given a link, decide whether it is phishing or safe
without ever training on that link’s own website. Formally, let U
be the set of all URLs, Y = {0, 1}, where 1 means phishing and 0
means safe, and let 𝑟 : U → R map a URL to its registered domain.
Given a labeled training set 𝐷 tr = {(𝑢𝑖 , 𝑦𝑖 )}𝑛𝑖=1 ⊂ U × Y, the task
is to learn a function
𝑓 :U→Y
that correctly labels a new URL 𝑢 whose registered domain never
appeared in training:

1

Introduction and Motivation

Phishing is when a fake link pretends to be a trusted website to steal
someone’s login or payment details. In 2025 alone, security groups
tracked over 3.8 million phishing attacks [2]. A good detector could
catch these links before anyone clicks them. Past work already
reports very accurate results [3], but that only matters if the detector
also catches brand-new attacker websites, not just ones similar to
its training data.

1.1

Motivating Example

Imagine a message that says: “Your PayPal account is locked. Fix it
here: https://paypal.login-fraud.top.” The word “paypal” sits in the
link, but the real website behind it is login-fraud.top, a domain
that has never been seen before. A useful detector needs to catch
links like this even though it never trained on that exact website.

2

Gap and Project Objective

Most testing methods split data randomly, so subdomains of one
company can land in both sets. The model is then not truly tested on
something new because it has already learned about that company.
Testing on a fully separate dataset can reduce scores by 10–32% [4].
Even a 2026 method that split by host still allowed 1,387 matching
registered domains across training and testing [1].
We will use the registered domain (for example, paypal.com) as
the unit that must never repeat between training and testing. We
compare a random split, a host-disjoint split, a registered-domaindisjoint split, and a cross-source split. Experiments use the 235,795site PhiUSIIL dataset [3] plus an independent public URL dataset.
Our contribution is a fair, reusable test protocol and a clear estimate
of how much the old style of testing overstates performance.
